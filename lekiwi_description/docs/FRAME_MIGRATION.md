# 최신 모델과 주행 좌표계 연결

2026-09-18부터 표시와 실물 bringup 모두 `urdf/lekiwi.urdf.xacro`를 사용한다.
몸체·바퀴·팔·전방/손목 카메라는 교육용 복사본이며, +X는 팔 정면, +Y는 왼쪽, +Z는 위다.
`base_footprint`는 바퀴 접지면, `base_link`는 그 위 0.075 m다.

## 모터 계산의 기준 변경

2026-09-18에는 기존 모터 ID `[7, 8, 9]`와 이름 순서 `[left, back, right]`, 극성을 유지했다.
이름은 모터 식별자이며 새 로봇 정면에서 보이는 바퀴 위치에 맞춰 다시 이름 붙이지 않았다.

2026-09-21 공중 검사에서 전진 명령으로 실물 뒤쪽·오른쪽이 회전해 ID 연결 오류가 드러났다.
토크를 끈 상태에서 뒤쪽 바퀴만 손으로 돌리자 ID 8이 -638 ticks, 왼쪽만 돌리자 ID 7이
+640 ticks 변했고 다른 ID는 그대로였다. 따라서 실물은 왼쪽 7·뒤쪽 8·오른쪽 9다.
현재 모델의 `left/back/right` joint는 각각 뒤쪽·오른쪽·왼쪽에 있으므로 활성 설정과
C++ 기본 ID 순서를 **`[8, 9, 7]`**로 수정했다. 모델 형상, 좌표 변환과 모터 극성은 유지한다.
이는 바퀴 ID 위치 연결의 수정이며 실제 6방향 구동과 라이다 방향 검증 완료를 뜻하지 않는다.

기존 URDF와 새 모델의 세 wheel mount를 비교해 다음 강체 변환을 확인했다.
`p_new = R_z(yaw) p_old + t`에서:

- `t = (0.007587843843, -0.010776931094, 0)` m
- `yaw = 2.094379865161` rad (약 +120도)

모터 좌표계 값은 `config/base_frame.yaml`에 있다. bringup은 이를 controller parameter로
로드한다. 단독 node 실행의 C++ 기본값도 같다. 2026-09-22 이후 센서 장착 TF는
`hardware_sensors.xacro`에서 별도로 설정하며 모터 좌표계의 yaw를 재사용하지 않는다.
이전 모델은 `test/fixtures/legacy_base.urdf`에 좌표 비교용 fixture로만 남겼다.

`/cmd_vel`은 새 base 좌표계의 속도다. 모터 계산 전에 회전과 기준점 offset의
회전 속도 성분을 적용해 기존 모터 좌표계로 변환한다. 엔코더 twist에는 역변환을 적용한다.
엔코더 위치 증분은 `R * delta + t - R(delta_yaw) * t`로 변환해 유한 회전 중
기준점 offset도 반영한다. wheel speed 제한은 이 변환 후에도 공통 배율로 적용한다.

## 장착 센서와 관절 표시

- 기본 모델 미리보기와 기본 ZIP은 카메라 2개를 포함한 18-link 모델이다.
- 실물 bringup은 `use_hardware_sensors:=true`로 같은 모델에 lidar/imu frame을 추가한다.
- IMU의 과거 장착 가정은 위 강체 변환으로 표현했으나, 아래 2026-09-22 임시 위치로 대체했다.
- 2026-09-22 사용자 제공 위치로 `soarm_base_link → lidar_link` 고정 TF를 갱신했다.
  SOARM base 기준 XYZ는 `(-0.02067, 0, -0.10250)` m (뒤로 20.67mm, 아래로 102.50mm)다.
  기존 `base_link → lidar_link` 직접 연결을 대체하며 중복 TF는 추가하지 않는다.
- 기본 팔 장착값에서 `base_link` 기준 XYZ는
  `(-0.000681720665, 0.001703025019, -0.049616)` m, 바닥 기준 높이는 `0.025384m`다.
  이 높이는 현재 모델의 base/팔 장착 높이를 합산한 결과이며 독립적인 바닥 높이 실측값은 아니다.
- 같은 날 사용자가 라이다 +X는 `base_footprint` +X와 같고 센서는 거꾸로 부착했다고 확인했다.
  이에 따라 기존 약 120° yaw를 제거하고 라이다 RPY를 `(π, 0, 0)` rad로 수정했다.
  기본 SOARM mount의 회전이 0이므로 base 기준 +X는 같고 +Y·+Z는 반대다.
  수평 스캔에서는 좌우가 반전되고, 수직 축은 아래를 향한다.
  위치값은 `lidar_link`의 스캔 원점에 적용했다.
- 드라이버 `reversion=false`, `inverted=true`와 위 TF를 함께 적용한 장비에서 방향을 확인했다.
  SDK에서 `reversion`은 각도에 π를 더하고, `inverted`는 각도 부호를 반전한다.
  기존 `inverted=true`는 유지하고 `reversion`의 추가 180° 회전을 해제했다.
  TF는 센서 장착 방향, 드라이버 옵션은 센서 원시 각도를 ROS 스캔 각도로 바꾸는 설정이다.
  사용자는 RViz의 `base_footprint` 기준에서 실제 물체의 앞뒤·좌우와 점 위치가 일치함을 확인했다.
  물체 비교 중 로봇 또는 물체가 이동했으므로 전후 스캔 차이로 정밀 방향·거리 오차를 계산하지 않는다.
- IMU 위치는 사용자 요청에 따라 라이다와 같은 X/Y, 로봇 기준 +Z로 50mm 위라는 **임시값**을 적용했다.
  `soarm_base_link → imu_link` XYZ는 `(-0.02067, 0, -0.05250)` m이며 실측 후 갱신한다.
  기본 모델의 `base_footprint` 기준 XYZ는 `(-0.000681720665, 0.001703025019, 0.075384)` m다.
  라이다의 +Z는 아래쪽이므로 `lidar_link` 아래에 단순히 +0.05m를 더하지 않는다.
  첫 수동 앞쪽·왼쪽 측정은 약 8° 차이가 있어 앞쪽 두 바퀴를 같은 높이로 드는 안내로 재측정했다.
  재측정의 가속도 변화는 yaw 86.35°, 이전 왼쪽 측정은 86.23°로 일치했고 두 축 사이 각도는 90.13°였다.
  각속도 적분 기준은 각각 87.36°·85.18°였다. 앞쪽 재측정 직전의 수평 회전 구간은 pitch 축 적분에서 제외했다.
  네 후보의 원형 평균 약 86.28°를 반올림해 당시 **yaw=86°**를 적용했다.
  2026-09-23 사용자 요청으로 현재 TF는 명목 직각인 **yaw=90°**로 변경했다. 두 각도의
  절대 정확도를 정지 중력·RViz 표시만으로 판별할 수 없으며 실물 기울임 재확인이 남아 있다.
  `axis_map=[1,2,3]`은 유지한다.
  앞서 적용했던 임시 82°를 대체한다. 같은 높이 받침 검사는 받침이 없어 취소했으며 추정에 사용하지 않았다.
  roll/pitch=0은 센서가 대략 위를 향한다는 장착 가정이다. 가속도 편차와 미세 기울기를 분리해 보정한 값이 아니다.
  수동 관측끼리의 일치를 절대 정확도로 해석하지 않으며, 이 TF는 정밀 장착 보정 완료를 뜻하지 않는다.
- controller의 바퀴 상태는 `/wheel_joint_states`로 전달되고 joint_state_publisher가
  표시용 팔 기본 자세와 합쳐 `/joint_states`를 발행한다. 팔 상태는 실측이 아니며 팔 제어는 없다.
- 기존 wheel position은 0을 발행하는 상태를 유지한다. wheel velocity와 odom은 별도 데이터다.

## 검증 범위

2026-09-18 활성 패키지 6개 빌드와 등록 테스트 188개가 통과했다.
세 wheel mount·센서의 강체 변환, 카메라 optical pose, 모터 명령과 twist의 왕복 변환,
엔코더 유한 회전, wheel saturation 및 기존 모터 안전 회귀 테스트를 확인했다.

mock/write-disabled/torque-disabled 실행에서 20-link 모델의 전체 TF, 관절 상태 9개,
`/cmd_vel` 구독과 command odom을 확인했다. 전진·좌측·회전 명령의 바퀴 속도가
좌표 변환과 일치했고, 명령 발행 중단 후 별도 zero 없이 timeout으로 정지했다.
이는 모의 명령·토픽 검증이며 엔코더 실측은 아니다.

위 2026-09-18 검증만으로 실물의 전후·좌우·회전 방향, wheel ID·극성 및 라이다 방향을
확정하지 않는다. 라이다 정지 상태의 앞뒤·좌우는 위 2026-09-22 현장 시각 확인으로 별도 기록했다.
라이다 거리 정확도, 이동 중 스캔 정합과 실물 SLAM 품질은 이 확인에 포함되지 않는다.
